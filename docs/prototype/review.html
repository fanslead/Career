DESIGN REVIEW · 2026.10.14

每一步，都知道发生了什么。

先做可操作的原型，再沿用户旅程检查方案。以下修正已写入界面、通信、生产实现与验收文档。

01 / 查看不改变状态

打开成果不是验收；打开许可不是批准。确认计划、工具许可和成果验收各自绑定对象与版本。

02 / 不同任务各自保留

收件箱、项目与成员负载来自同一任务状态；异步回复、消息草稿和交接说明不能写到另一个任务。

03 / 失败后不用重填

任务草稿和非敏感连接字段保留；模型参数变化后重新测试。页面、弹窗都遵守同一离线操作限制。

04 / 结果未知就先核对

邮件可能发出时不自动重发。先查询，或记录有依据的结论；SMTP 接受也不等于进入收件箱。

05 / 键盘与小屏都能继续

页面切换、页签重绘和弹窗关闭保留合理焦点。手机导航可关闭，审批、核对与验收使用单列布局。

06 / 知道哪里还需要验证

示例费用、回执、引用与测试不是生产证据。原型验证不替代真实后端、平台、账号与服务检查。

生产实现必须走通的六条旅程

  1. 第一项任务：输入 → 工作区 → 模型连接 → 失败恢复 → 确认计划。
  2. 外部动作：预览固定内容 → 有限许可 → 收到回执，或保持待核对。
  3. 成果交付：检查来源 → 退回修改 → 新版重新验收 → 任务完成。
  4. 暂停接管：收到执行者确认 → 保留成果 → 安全交接，未知时冻结相关资源。
  5. 资料与记忆：导入 → 版本与引用 → 更正/共享 → 归档或遗忘。
  6. 状态一致：切页、切任务、断线重连和版本冲突时，不丢输入、不串状态。

阶段描述验收范围，不承诺工期，也不表示当前已经开工或完成。

| 阶段 | 验收范围 | 主要场景 ID | 放行条件 |
| --- | --- | --- | --- |

| P1 | 一项可交办、执行、产出并验收的任务闭环 | `TASK-*`、`PLAN-*`、`LIFE-*`、`BUS-*` 的单成员本地路径 | 用户可从轻量任务开始；Task 验收和 Run 终态分开 |

| P4 | 汇报、备份恢复、部署和长期运行体验 | `SIDE-SMTP-*`, `OPS-*`, `UX-*` | 受控外部效果和恢复路径有环境对应的证据 |

## 3. 岗位、责任与任务对象验收矩阵

| `ROLE-02` | 建两个同岗位长期成员，分别接任务并写入私有经验 | 共用岗位模板不等于共享对话或私有记忆；未显式发布的经验对另一个成员不可见 | 未验证 |
| `ROLE-03` | 长期成员委派临时调研子任务，随后查看任务与成员记录 | 委派生成持久 child Task/Run；临时执行身份不自动成为长期成员或获得长期记忆写入权；责任仍可追溯到委派人 | 未验证 |
| `ROLE-04` | 将临时身份保存为长期成员 | 是单独、可审计的配置动作；只保存明确选择的身份/能力/经验；不复制全部临时上下文、审批或私有资料 | 未验证 |

| `TASK-02` | 修改活跃任务的目标、收件人、验收或写入范围 | 创建新 revision 并使不适用的候选成果/审批失效；不能静默改写正在执行的 Run 输入 | 未验证 |
| `PLAN-01` | 计划确认前后重启；重复同意，再修改 taskRevision 或提案内容并使用旧决定 | 同一 TaskDecision 和待决项可恢复；重复决定只处理一次；旧 revision/hash 不放行；同意计划不授予 Operation 权限或完成成果验收 | 未验证 |
| `LIFE-01` | 对同一 Task 做一次初始执行、一次兼容恢复、一次目标变更后的返工，再仅刷新浏览器 | 同任务多 Run、同 Run 多 Attempt；返工使用新 Run；仅界面重连不创建新 Task、Run 或 Attempt | 未验证 |

| `CHILD-02` | 分别令必需子任务失败、可选子任务失败、依赖成功 | 必需失败会阻塞；可选失败仅在验收规则允许时继续并记录缺项；父 Task 不由 child Run 成功数量直接判定完成 | 未验证 |

| `LIFE-02` | 同一逻辑工具步骤恢复；模型重跑产生新的 provider callId | Run/步骤/工具槽位映射到同一 Operation ID；相同参数返回或核对原结果，不以新 callId 绕过未知 Operation | 未验证 |

## 5. 进程崩溃与启动恢复矩阵

按 [13 第 7 节](13-restart-and-recovery.md) 的持久化边界，在各行标出的提交点前后终止进程。每次恢复检查 SQLite 事实、旧 Worker/Runner 是否停止、真实工具目标、UI 状态和预算；不能只检查模型回答。

| 场景 ID | 故障注入点 | 重启后的通过判据 | 状态 |
| --- | --- | --- | --- |
| `CRASH-01` | Task/Run 已入队，尚未领取 | 校验 revision、依赖、范围和取消意图后最多重新调度一次 | 未验证 |
| `CRASH-02` | 领取/Attempt 已落库，工具尚未派发；旧 Worker 可能仍存活 | 新 hostEpoch 使旧提交资格失效；先停旧写者或冻结资源，再从兼容安全点建新 Attempt | 未验证 |
| `CRASH-03` | 模型流中断，尚未提交完整消息或工具调用 | 保留已提交水位；标记不完整 attempt；无未决副作用时才可重试模型步骤，费用不重复归零 | 未验证 |
| `CRASH-04` | 等待审批时终止 Host | 重建同一待决对象；不执行工具；保留审批范围和有效期 | 未验证 |
| `CRASH-05` | Approval 已批准，Operation 尚未派发 | 核对批准快照和当前策略后才排队；不新建逻辑 Operation | 未验证 |
| `CRASH-06` | Operation 进入 `Executing` 后，目标可能已执行但无确定回执 | 进入结果待核对；依目标合同查询/核对；无证据时不自动重发 | 未验证 |
| `CRASH-07` | 工具成功及回执已落库，最终模型回复尚未完成 | 复用已保存工具结果完成 Run 收尾；Operation 不再次执行 | 未验证 |
| `CRASH-08` | 成果文件已发布、内容写到一半或 hash 登记提交中断 | 完整匹配则补登记；损坏/冲突则隔离；不把半写文件交付、不覆盖已存在的不同版本 | 未验证 |
| `CRASH-09` | Run 已成功，Task 尚未验收 | 重建固定 Artifact 版本和待验收项；不重跑 Run，不把 Task 自动标为 Done | 未验证 |
| `CRASH-10` | 父 Run 等待 child；父子完成事件并发或其中一方重启 | child 关系和结果水位持久；同版本只合并一次；再依汇总/验收规则推进父任务 | 未验证 |
| `CRASH-11` | 暂停/取消请求已持久化，安全停止尚未完成 | 恢复时先处理持久意图；取消不自动重新排队；未知副作用进入对账而非伪报已取消 | 未验证 |
| `CRASH-12` | checkpoint 损坏/不兼容、权限撤销或记忆在运行后被撤回 | 阻塞不可安全续接的 Run；重查当前授权和记忆撤回；保留历史/成果并给接管入口 | 未验证 |
| `CRASH-13` | 从含有旧任务/审批/操作记录的备份恢复 | 先进入检查/恢复模式；禁止自动外发；核对备份之后可能发生的真实动作和撤回记录后才能开放调度 | 未验证 |

## 6. 真实副作用与对账矩阵

这些场景需要操作真实但隔离的目标资源，而不是只验证假工具回调。执行前使用一次性测试目录、测试收件箱或可清理测试端点；本轮只实际验证 P0 隔离目录内的专用文件回执，其他目标尚未触发。若目标不提供可靠幂等或查询合同，正确结果是保留 `UnknownOutcome` 并等待人工核对，不把自动重试作为通过条件。

| 场景 ID | 实际目标与故障窗口 | 通过判据 | 状态 |
| --- | --- | --- | --- |
| `SIDE-FILE-01` | 在隔离工作目录创建/发布不可变文件；分别在暂存写入、原子发布、hash 读回、数据库登记前后终止进程 | 目标文件最多有一个可交付版本；其 hash 与 Operation/Artifact 对应；半写或孤儿文件被隔离/补登记，不覆盖不同内容 | 未验证 |
| `SIDE-HTTP-01` | 对专用测试端点做带幂等键的创建操作，在目标接受后丢弃响应 | 重启后以相同键和相同参数查询/重试，目标只有一个逻辑记录；过期或参数不同按合同冲突/人工核对 | 未验证 |
| `SIDE-SMTP-01` | 向明确授权的测试收件箱发送固定正文，在 SMTP 接受后丢弃本地确认 | Outbox 保留同一批准内容与 Message-ID；可查时记录接受证据，不可查时标结果未知并阻止自动重发；不把“SMTP 已接受”显示成“已送达” | 未验证 |
| `SIDE-SHELL-01` | 在一次性目录运行确有写入副作用的命令，在命令启动后/完成后强制结束进程 | 核对旧进程停止、资源锁和实际文件；结果未知时冻结冲突写入并等待核对；不因命令字符串相同而宣称幂等 | 未验证 |
| `SIDE-EXT-01` | 用可查询的测试外部系统完成一次更新，再覆盖“接受后回执丢失”和重复 webhook | 稳定 Operation ID/幂等合同只产生一个目标效果；重复接单仍关联原 Task；查不到效果时显式保留未知状态 | 未验证 |

## 7. 记忆与知识验收矩阵

依据 [06](06-memory-and-knowledge.md) 的对象和发布规则。验收同时检查权威文件/清单、候选数据库记录、派生索引、ContextManifest 与用户可见状态；不能只看模型最终回答。所有场景目前未验证。

| 场景 ID | 场景与验证动作 | 通过判据 | 状态 |
| --- | --- | --- | --- |
| `MEM-SCOPE-01` | 在成员私有、项目、岗位和工作区范围各发布一条有来源的记忆；让同岗位其他成员及临时子 Agent 检索 | 只返回当前任务显式绑定且允许的范围；同岗位不泄漏成员私有记忆；临时子 Agent 仅获得交接包和明确授权条目；不能从目录位置推断权限 | 未验证 |
| `MEM-PUBLISH-01` | 分别提交“记住这个”、自动经历摘要、推断偏好、证据支持的事实、已验收岗位方法和私有条目共享请求；在候选检查、正文写入、清单更新及确认记录之间终止进程 | 按 06 的来源类型与目标范围执行确认规则；推断保持 Candidate；低风险摘要仅作为经历；岗位方法带适用前提；共享需显式目标和来源可见性检查；重启按 operationId/hash 补记同一发布，不重复建条目 | 未验证 |

| `MEM-TIER-01` | 创建 Hot、Warm、Cold、过期和归档条目；在普通新任务、定向搜索及恢复后分别检索 | Hot 仍按相关性和预算筛选；Warm 按查询召回；Cold/归档不默认注入但可显式查找；仅因访问频繁不能恢复过期事实；冷热变化不复制或移动权威正文 | 未验证 |

## 10. 证据记录与验收结论

每个场景分别记录：场景 ID、依赖版本/commit、OS/RID、数据库 schema、输入和授权范围、故障注入的持久化边界、操作步骤、Task/Run/Attempt/Operation/Approval IDs、进程与租约状态、重启前后数据库快照、真实文件/目标系统查询结果、事件日志、界面下一步、预算变化，以及原始日志/成果引用。

最终状态只能是：**通过**（证据满足全部判据）、**失败**（判据不满足）、**未验证**（未运行或证据不足）。静态代码审查、脚本存在、单元/Worker 独立场景和发布成功都要按其实际范围记录，不外推为端到端通过。任何真实副作用不确定时，保留 `UnknownOutcome`、证据和人工核对结果；不能为了把矩阵改绿而盲目重放。

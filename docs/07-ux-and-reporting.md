# 界面、运行监控与 SMTP 汇报

更新：2026-10-14。首版为浏览器工作台；根据研究调整为任务优先、配置按需出现。桌面壳取舍见 [React 与 Electron](12-react-and-electron.md)，恢复呈现依据 [13](13-restart-and-recovery.md)。

## 1. 菜单按工作组织

一级菜单保留五项；对话与能力仍可直接找到，但不占两个额外主菜单：

| 菜单 | 默认内容 | 常用操作 |
| --- | --- | --- |
| 工作台 | 交办入口、收件箱、等我处理、近期成果和对话历史 | 新建任务、纯聊天、继续、处理确认 |
| 项目 | 项目列表，项目内有需求、任务看板与成果 | 提需求、调优先级、看依赖、验收 |
| 团队 | 岗位和 AI 成员、当前负载、能力 | 加成员、改职责、分配技能与连接 |
| 资料 | 知识库和记忆两个页签 | 导入、查来源、纠正记忆、重建索引 |
| 设置 | 模型、工具连接与插件、邮箱、预算、工作区与备份 | 测试配置、安装、启停、导出、恢复 |

三种模式切换放在工作区顶部。它改变首页快捷任务、岗位建议和项目模板，不隐藏全部其他能力，也不重置现有工作。

“Agent”“MCP”“Embedding”“AOT”可以在帮助和高级设置出现；常规页面优先用“AI 成员”“工具连接”“知识检索模型”等容易理解的名称。

## 2. 首次使用

1. 首页先提供“你想完成什么”与办公/研发/经营示例；输入立即保留为草稿。
2. 首次保存时确认工作区位置，允许接受默认目录并说明数据归属；不要求先建立岗位。
3. 模型缺失时就地连接并测试，完成后回到同一草稿；只有聊天能力时明确不能执行工具任务。
4. 运行前展示目标、输入、默认负责人、成果和必要目录范围；简单任务可直接用默认助理，模式和成员可稍后调整。
5. 真正需要知识检索、外部服务或发信时再配置 Embedding、连接器和 SMTP。补齐后继续原任务，不要求重新输入需求。

用户填写连接失败时保留非敏感输入，区分地址、认证、模型名、网络和能力问题。错误提示给一个下一步，而不是把供应商堆栈直接贴到界面。

## 3. 工作台与任务详情

工作台优先显示“需要你处理”的卡片，其次是进行中任务和最近完成成果。全局保留“暂停新任务”与“紧急停止运行”，不要让用户到处找停止按钮。

任务详情包含目标与验收、负责人、阶段、当前动作、活动记录、成果、相关资料和对话。默认展示人能理解的摘要，工具参数、模型用量与调试详情折叠。

同一页分清“责任人”和“当前执行者”，临时子 Agent 标为一次分工；子任务折叠显示负责人、结果与阻塞。改派显示交接中和下一步，完成责任切换前不假装新成员已接手。成果页以固定版本列出验收项、证据、通过/退回和未验证项；Run 成功不能直接把任务卡片标为完成。

Agent 卡片至少显示：岗位、当前任务、阶段、当前动作、最近活动时间、耗时、费用、是否等待用户。没有活动不代表死机；无心跳与无进展分别呈现。

进度表达优先“已验收 3 / 5 项”“正在核对第 2 份资料”。不知道剩余工作量时显示阶段，不生成装饰性百分比。真实工具回传的进度可显示，并注明其对应步骤。

刷新、断线、切换页面不停止 Run。重连显示正在补齐状态；事件有缺口时重新取快照。取消提交后显示“正在停止”，收到后端终态才显示已停止。

服务重启另外显示恢复结果：可继续、等你确认、正在核对、需要接管。结果未知时解释已知内容和受影响范围，提供“查询结果/记录核对结论”，不默认放一个会重新执行的重试按钮。工具已经完成但回复未完成时显示“动作已完成，正在整理结果”。

## 4. 确认与接管

确认卡片展示：谁要做什么、作用对象、关键内容、文件差异或收件人、授权范围与有效期。常用按钮为“允许一次”“允许此流程”“拒绝”；高风险动作不提供含糊的全局放行。

用户补充新要求时区分“仅发消息”“调整当前任务”“暂停后修改计划”；运行中不能把一条聊天文字无声变成对已批准外部动作的内容修改。参数改变后校验原授权是否仍适用。

计划确认、工具许可、成果验收采用不同标题和对象预览。比如“同意这份计划”不会授权发邮件；“允许发送”不会表示邮件已送达；验收报告 v1 不会自动验收 v2。表单带版本，发生冲突时保留输入并展示已变化的对象。

接管时保留已完成内容和明确下一步，能改派其他成员；不要求用户阅读整段工具日志才能继续。

资料页的记忆条目展示范围、来源、版本、确认状态和使用记录；私有发布到共享前展示实际内容与影响对象。归档与忘记分开：前者仍可搜索，后者停止未来注入并清理所选副本。在途模型已收到的内容无法撤回，UI 说明受影响任务是否需要重建上下文。

## 5. 视觉与可访问性

亮色底色、柔和的蓝／青强调色，半透明材质用于侧栏、顶栏和少量浮层。正文、数据表与长时间阅读区域采用足够不透明的背景，保证文字对比和密集信息的可读性。

避免大面积模糊叠加、持续动画与装饰性虚拟办公室占据任务空间。毛玻璃不依赖 Electron；浏览器中的 CSS 也可以实现，低性能或减少透明度偏好时退化为纯色。

验收覆盖键盘访问、清晰焦点、屏幕阅读器标签、减少动画、200% 缩放、窄屏任务操作。状态不能只用颜色表达；看板卡片有列表替代视图。弹窗关闭和保存失败保留用户输入。

第一版桌面宽屏优先，但手机浏览器至少能看进展、处理确认、暂停任务；复杂配置和大表格允许明确的适配布局，不挤成不可用的小字。

## 6. SMTP 配置与收件人

设置项：SMTP 主机、端口、加密方式、账号、密码／应用专用密码、发件人名称、发件地址、默认收件人和可选 Reply-To。凭据只保存 secretRef；支持连接测试与单独的试发邮件。

收件人是独立通讯录，可被项目汇报策略引用。项目和任务可覆盖默认收件人，但新收件人或超出授权范围的外发需要确认。连接测试不自动发信，试发需清楚展示目标。

默认使用安全的 TLS 配置；是否支持匿名认证等特殊环境由高级设置控制。SMTP 库运行在通过兼容验证的 Host 或专用普通 .NET Worker 内，不为 AOT 目标强行选择不成熟实现。

## 7. 汇报规则

| 时机 | 默认建议 | 内容 |
| --- | --- | --- |
| 开始 | 可选，默认关闭 | 目标、负责人、计划和预算 |
| 达到里程碑 | 项目可开 | 已交付什么、还剩什么 |
| 受阻／失败 | 有行动价值时发送 | 已确认原因、影响、用户可采取的下一步 |
| 等待确认 | 可开 | 具体决策和工作台入口；不直接在邮件链接里执行动作 |
| 完成 | 默认建议开启 | 成果摘要、验收结果、成本、附件或可达链接 |
| 每日／每周 | 可配置 | 汇总变更、待办与异常，避免重复推送 |

时间规则保存时区，第一版默认使用工作区时区。相同事件按 notification ID 去重；合并短时间连续更新，支持静默时段。定期汇报没有新增内容时可以不发。

通知读取已提交任务状态、成果版本和验收记录生成。若邮件只是汇报渠道，发送失败只进入通知异常，不倒改已验收任务；若发送是任务必需交付项，则结果明确前任务不能完成。通知重启和未知结果处理沿用 Operation 账本。

本地 `localhost` 链接无法被其他人访问。远程收件人应收到允许外发的附件、正文摘要或已配置的可达工作台地址，不能把本机绝对路径当成可用成果链接。

## 8. 可靠发送

发送前保存最终正文、收件人与内容 hash、授权依据和 outbox 记录。重试必须发相同已批准内容；Agent 后续改稿需创建新版本。

状态至少区分待发、发送中、SMTP 已接受、明确失败、结果待核对。SMTP 接受不等于收件箱最终送达；没有 DSN 等证据时不显示“已送达”。固定 Message-ID 便于跟踪，但不能保证收件系统去重。

若发送后断线而接受状态未知，保留待核对，不能无条件重发。首次配置后的试发和恢复演练必须覆盖这个窗口。邮件正文默认不包含密钥、完整提示词或整段原始工具输出。

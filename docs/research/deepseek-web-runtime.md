## 纯 Web 形态、启动与部署

**官方说明：** npm 入口是 `npx @deepseek-ai/dsh web`，默认在 `127.0.0.1:3080` 启动并尝试打开本机默认浏览器；源码工作流明确先 `pnpm install`、`pnpm run build`，然后 `pnpm dsh web`，启动命令直接使用既有构建产物，不负责构建。[README.zh.md：运行方式与构建边界](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/README.zh.md#L21-L45)

**源码观察：** Web 入口把 `--host`、`--port`、`--no-open`、`--public-url`、可重复的 `--trusted-host` 和成对的 TLS 证书/密钥作为 Cordis 服务提供；拒绝通配绑定地址、非法端口和只给出一半的 TLS 配置。[Web 启动参数](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/bundle/web-app/src/startup.ts#L59-L123) Web 组合把 Web 载体、静态前端、Connection 与浏览器模块注册表装入同一个 profile。[Web profile 组合](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/bundle/web-app/cordis.patch.yml#L216-L236) URL 行与浏览器交接等待 Loader 启动审计完成后再发出。[就绪门](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/bundle/web-app/src/index.ts#L267-L307)

**官方部署约束：** 默认只监听 loopback；远程浏览器要通过可信主机 authority 访问。`--public-url` 只是对外公告，不会配置监听地址、路由、信任或 cookie 路径。反向代理需保留浏览器可见的 `Host`，剥去外部挂载前缀，转发 WebSocket Upgrade，并将 cookie `Path` 改写到挂载路径；浏览器可见 authority 需另列为 `--trusted-host`。监听端口仍须限制在代理或可信网络内。[反向代理部署要求](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/docs/user/guide/public-deployments.zh.md#L11-L35) 官方 Web 参考再次区分公告 URL 与接纳 authority，并说明 TLS 可以由代理或监听器终止。[Web 参考](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/bundle/web-app/README.zh.md#L60-L81)

**源码观察：** 首次打开根路径时，进程凭据经 token 校验后换成带 HMAC 签名、绑定访问 authority 的 HttpOnly、SameSite=Strict cookie，随后 303 到干净的 `./`；监听器本身启用 TLS 时 cookie 带 `Secure`。[认证 cookie 属性](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/connection/src/browser-auth.ts#L121-L139) [Token 交换与认证](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/connection/src/browser-auth.ts#L250-L313) 静态前端只对 index 文档要求该浏览器认证，其他前端资源公开读取；`/api` 请求另经认证、Host/Origin 与 cross-site 检查，信任栅栏本身不代表身份。[静态 index 认证](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/host/frontend-static/src/index.ts#L61-L105) [API 信任栅栏](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/connection/src/api-request-trust.ts#L113-L151)

## 浏览器前端装配与输入链

**源码观察：** Web app 是普通浏览器入口，导入共享的 `AppWebEntry` 并启动。[浏览器入口](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/web/src/main.ts#L1-L40) Host 侧 `ClientModuleRegistry` 扫描已加载 package 的 `dsh.client` 声明，为 `platform: web` 且导出 `./client` 的包生成 revision 化 bundle 路由和 `__DSH_BOOT__` 图；启动时对缺失或错误声明作硬失败。[Web package 识别](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/src/index.ts#L828-L858) [模块图与路由注入](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/src/index.ts#L589-L657) 浏览器等待注入门，创建模块系统，按清单逐项启动 Cordis 插件、审计激活状态，再挂载 UI。[浏览器 boot](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/web/src/boot.ts#L43-L103) [Loader 组合与启动审计](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/web/src/boot-client.ts#L27-L57)

**完整输入链（源码观察）：** Composer 的 `sendSession` 先校验草稿附件，立即显示 pending submission；图片在浏览器侧编码为 prompt 内容，普通文件先上传并以 receipt 引用，随后调用 `session.prompt(content, mode, …)`。[Composer 提交与附件序列化](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-conversation/src/client/service.ts#L229-L297) Web `Session.prompt` 生成 request ID、附带 session、queue/steer 模式与客户端时区，通过 `remote.session.prompt` 发起调用。[Session prompt](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/client/sessions/session.ts#L254-L315) Remote client 将普通调用交给 Connection 的 `/api` RPC；浏览器传输以 JSON POST 到文档相对的 `api/session/prompt` 路由，并校验响应 RPC ID。[Remote 普通调用](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/index.ts#L431-L461) [浏览器 RPC POST](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/connection/src/client/rpc.ts#L34-L69) Host 的 `SessionController.prompt` 检查取消信号并将请求交给 `commands.prompt`。[Host prompt 入口](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/index.ts#L435-L445)

## 流式输出与重连

**源码观察：** 普通请求走 `/api` HTTP RPC；Remote 流共用 `/api/remote.mux` WebSocket 物理连接，每条逻辑流有自己的 stream ID、打开/取消/数据帧。Gateway 对 WebSocket upgrade 重用 Connection admission 检查。[WebSocket 路由与准入](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/index.ts#L240-L263) [Remote 流路径](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/stream-protocol.ts#L1-L16) [复用物理连接并多路复用逻辑流](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/stream-client.ts#L46-L56) [打开逻辑流](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/stream-client.ts#L88-L145)

Session UI 打开 `SessionEventStream`，经 `remote.session.follow` 订阅 Host 事件日志。首次帧包含事件快照、水位 cursor 和可选 assistant stream baseline；后续帧是有序持久事件或带 revision 的 assistant-stream 更新。[客户端 follow 解码](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/client/transport.ts#L171-L220) [Host follow 快照与事件尾随](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/history.ts#L120-L220) Host 方法是明确的 stream Remote。[Session follow Remote](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/index.ts#L488-L497)

承载层失败时，RemoteStream 将它分类为可重试错误，等待 Connection 出现新一代 Host 后重新打开；Journal 消费端保存 cursor，接受新 generation 的 opening snapshot，忽略已应用 cursor，并在发现序号缺口时读历史页补齐。这里的重连是重新打开逻辑流并对齐领域 cursor，源码没有把旧 WebSocket 的帧本身重放。[Carrier 重试生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/remote-stream.ts#L31-L38) [错误分类与重开](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/remote-stream.ts#L95-L157) [Journal cursor/缺口处理](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/journal-stream.ts#L261-L335) 是否在断网、代理切换或进程重启时达到预期时延与 UI 表现，未实测。

## 审批 UI 的完整往返链

**源码观察：** Host `ApprovalService.request` 只接受正在打开的 Agent turn；先追加 `approval/asked`，再派发 `approval/request` waterfall，最后追加 `approval/decided`。没有答复者、答复者异常或非预期结果都会 fail-closed；取消信号也会收敛为取消结果。[Host 审批记录与判定](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/index.ts#L210-L233) [fail-closed waterfall](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/index.ts#L261-L307)

**完整审批链：** Host 事件桥把 Agent-scoped `approval/request` 包成只包含可序列化请求和 Agent ID 的 Remote waterfall frame；Gateway 给连接中的浏览器 Client 投递该 frame并持有未决事件。[Host waterfall 转发](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/remotes/src/index.ts#L48-L79) [Gateway 创建并投递待决事件](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/index.ts#L549-L633) 客户端按 Agent 所属 Session 找到目标 composer，把请求注册为待处理交互；UI 展示原因和可选工具详情，允许“仅本次允许”或拒绝，也支持 Enter/Esc。[浏览器接收与 Session 绑定](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-approval/src/client/index.ts#L35-L106) [审批界面动作与快捷键](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-approval/src/client/ApprovalPanel.tsx#L21-L87) 客户端把 outcome 发到 `$events/result` HTTP RPC；Gateway 以 client/event ID 核对投递关系并 settle 原 waterfall，Host 接到 outcome 后完成 `approval/decided` 记录。[Client 处理与返回结果](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/client/remote-events.ts#L186-L250) [Gateway 结算结果](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/gateway/src/index.ts#L614-L633)

## 插件安装、装配与隔离界面

**源码观察：** Web 的“插件”侧栏页是 profile 范围的全局页面，不属于单个 Session；它调用 `remote.pluginManager` 安装、启用、禁用、移除 profile bundle，并监听 Host 的变更、安装日志和进度事件。[插件页职责与事件订阅](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/index.ts#L1-L10) [管理页 Remote 依赖和状态订阅](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/index.ts#L68-L100) [Web profile 提供管理器行](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/bundle/web-app/cordis.patch.yml#L310-L320)

普通插件启用/禁用经 Remote 持久化 profile patch 并尝试 reload；bundle 安装会由 Host 在 profile 目录执行 `pnpm add`，插件页可 inspect 规格，并显示安装日志/状态。[UI 启用、禁用、删除调用](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/manager-store.ts#L650-L680) [UI inspect 与 install RPC](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/manager-store.ts#L930-L980) [Host profile 包管理](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/boot/plugin-manager/src/index.ts#L485-L566)

若 pnpm 因被忽略的依赖构建脚本而失败，UI 列出待审批包名，用户显式点“允许并重试”；Host 将逐个包名写入 profile workspace 的 `allowBuilds: true`，再重跑安装。[审批 UI](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/PluginManagerPage.tsx#L1270-L1288) [重试携带已批准包名](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-plugin-manager/src/client/manager-store.ts#L1052-L1062) [profile 持久许可](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/boot/plugin-manager/src/build-approval.ts#L70-L80)

**隔离边界推断：** 有两层插件面：Node Host Loader 负责服务端插件，`dsh.client.platform=web` 包还可带浏览器 `./client` bundle；Host 组合模块图并提供浏览器脚本，浏览器把这些 factory 装入单页模块表和 Cordis 插件树。[包声明选择](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/src/index.ts#L828-L858) [浏览器模块系统](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/src/client/manifest.ts#L1-L29) 这提供插件生命周期、依赖注入和启停状态管理；这些引用没有显示 browser 插件使用独立 iframe/worker 或 OS 进程沙箱，也没有证据表明 Host 插件脱离当前 Node Host 进程执行，因此不应把 Loader 作用域等同安全隔离。此结论是源码结构推断，未作安全测试。

## Web 与 Desktop 边界

**官方说明与源码观察：** Desktop 是 Electron 壳复用 Web 应用。它用 `dsh-app://app/` 从本地打包目录加载前端静态文件，其他应用请求通过主进程代理到已经认证的本地 Host；主进程保管 Host cookie 并转发 WebSocket 流。[Desktop 形态说明](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/desktop/README.zh.md#L7-L9) [Electron 本地协议路由](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/desktop/src/main.ts#L664-L679) [认证与转发实现](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/desktop/src/web-document.ts#L38-L92) `apps/web` 同一入口通过 `dshDesktopBoot` 的存在与否选择 Web 的现成注入或等待 Electron IPC 提供注入。[共用入口的 Desktop 分支](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/apps/web/src/main.ts#L5-L39) 所以纯 Web 部署的浏览器直接访问 Web Host origin；Desktop 则多出 Electron 本地 origin、主进程代理和 IPC 层，并不等同“仅一个浏览器静态站点”。

## 适合带回产品讨论的边界结论

可以借鉴的具体机制是：普通写请求与长流分离（HTTP RPC + 多路复用 WebSocket）；长流携带领域 cursor 并在新 generation 用快照重开、校验连续性；需要用户决策的运行时 waterfall 可投递到对应 Session composer 并把结果回传原调用；插件安装脚本批准采用失败后列出精确包名、显式确认、按 profile 持久授权的流程。这里记录的是仓库已实现的来源机制，不评估它们对我们产品的整体适配。

**未验证限制：** 本次为静态源码阅读；未实际启动 `dsh web`、验证反向代理/TLS/cookie、发送模型请求、断网重连、回答审批、执行插件安装或检查操作系统权限隔离。部署和安全行为仍需相应环境实测才能作为产品验收结论。

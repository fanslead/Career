# 开源 Agent / 知识库项目核查

只读核查三个 GitHub 一手仓库；基线为 2026-10-14 当日查询到的提交。README 和产品文档中的能力标为“官方声明”，代码/数据模型标为“源码”。未运行项目或独立复测。以下是各项目自身的机制与边界，不把它们互相代入。

## Paperclip — 组织与 Agent 工作控制面

核查提交：[2c17d3ca52a7840f280f1dd87975a2ad77de3b35](https://github.com/paperclipai/paperclip/commit/2c17d3ca52a7840f280f1dd87975a2ad77de3b35)；[MIT LICENSE](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/LICENSE)。

1. **岗位与汇报线（源码）**：Agent 记录有 `role`、`reportsTo`、`capabilities` 和月预算；README/组织文档把岗位、职称、汇报对象和组织树作为一等概念。见 [`agents.ts`](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/packages/db/src/schema/agents.ts#L20-L57) 与 [org structure 文档](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/docs/guides/board-operator/org-structure.md)。
2. **任务与调度（源码 + 官方运行指南）**：Issue 可连到公司、项目、目标、父任务和负责人，保存状态、审查策略、执行策略及 checkout/execution 锁；Agent 通过 timer、assignment、on-demand、automation 等 wakeup 运行，重复 wakeup 会合并，队列控制并发准入。见 [`issues.ts`](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/packages/db/src/schema/issues.ts#L26-L89)、[Agent Runtime Guide](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/doc/spec/agents-runtime.md#L200-L242) 与 [`queue.ts`](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/server/src/services/heartbeat/queue.ts)。
3. **预算（源码 + 官方文档）**：预算策略可设周期、预警比例和硬停止；达到硬上限默认暂停 Agent。成本来自运行器上报，官方文档指出使用记录支出，实际费用归集和停止时机会受上报与运行中工作影响。见 [`budget_policies.ts`](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/packages/db/src/schema/budget_policies.ts#L5-L46) 与 [README 成本说明](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/README.md#L296-L299)。
4. **审批（源码 + 官方文档）**：Agent 提交的招聘申请进入 Board 审批，含岗位、能力、运行器配置及预算；CEO 初始战略也可要求人工批准。审批状态和请求载荷落在独立记录中。见 [Approvals 文档](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/docs/guides/board-operator/approvals.md#L6-L36) 与 [`approvals.ts`](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/packages/db/src/schema/approvals.ts#L5-L27)。
5. **运行器与插件（官方声明/规范）**：Paperclip 管理 heartbeat，具体 Agent loop/身份配置由适配器定义。README 宣称插件提供 out-of-process workers、工具、调度任务和 UI；但插件规范标注为 post-V1 目标，现阶段 UI 与主应用同源运行，能力声明只约束 worker 侧 host RPC，不构成 UI 沙箱边界。见 [Agent runtime spec](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/doc/SPEC.md)、[README 插件说明](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/README.md#L308-L308) 与 [plugin spec](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/doc/plugins/PLUGIN_SPEC.md#L194-L218)。
6. **边界**：核心是组织/任务控制面，不含知识库；SPEC 明确把知识库列为未来插件。此仓库是 Node.js + React，DB schema 使用 PostgreSQL 方言，并以嵌入式 PGlite 作为开发体验，因此不能作为 .NET Agent loop、SQLite 主存储的直接实现证据。见 [README](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/README.md#L37-L45)、[`agents.ts` schema](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/packages/db/src/schema/agents.ts) 与 [SPEC](https://github.com/paperclipai/paperclip/blob/2c17d3ca52a7840f280f1dd87975a2ad77de3b35/doc/SPEC.md#L632-L646)。

## AIDotNet/NextCoWork — 桌面 coding harness

核查提交：[b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917](https://github.com/AIDotNet/NextCoWork/commit/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917)；主仓库 [Apache-2.0 LICENSE](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/LICENSE)，插件生态包另声明 MIT（README）。

1. **实现栈边界（源码树 + 官方声明）**：该提交的 README 描述 Electron 桌面端、React renderer 和 Node.js device service；递归仓库树中未发现 `.cs`、`.csproj` 或 `.sln` 文件。因此不能将搜索索引中偶见的“.NET 10 Native AOT worker”表述当作当前 NextCoWork 源码事实，也没有证据证明它支持 AOT。见 [README 项目结构/运行方式](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/README.md#L256-L288) 与 [该提交文件树](https://github.com/AIDotNet/NextCoWork/tree/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917)。
2. **Agent loop（源码）**：`AgentSession` 实现 think → tool → observe；以流式上游、工具注册表和显式 `approve`/`interact` 接缝组装一次会话。注释说明会话本身不重试，重试交给上游路由，以避免重复执行工具调用。见 [`agent-session.ts`](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/main/kernel/agent-session.ts#L1-L12) 与 [依赖接口](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/main/kernel/agent-session.ts#L69-L150)。
3. **逐工具审批（源码 + 官方声明）**：README 声明 tool call 带审批链；实现中对每次调用结合权限模式、只读/破坏性/联网属性、本地规则和钩子判定，再返回 allow/ask/deny；人工交互由独立 gate 处理。见 [`approval.ts`](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/main/kernel/approval.ts#L171-L210) 与 [`permission-gate.ts`](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/main/kernel/permission-gate.ts#L13-L46)。
4. **子 Agent 与计划任务（源码）**：子 Agent 有容量接口及显式队列；队列常量限制每个 parent 最多 16 个等待项、全局最多 64 个等待项，避免模型过量派发。README 另列 background tasks 与 scheduled runs。它是 harness 内的并发控制证据，不等同于持久化的公司任务调度系统。见 [`subagent-queue.ts`](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/main/kernel/subagent-queue.ts#L18-L83) 与 [README 特性](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/README.md#L234-L246)。
5. **技能/MCP/插件（源码 + 官方声明）**：项目使用自己的 manifest/API；插件可贡献工具、命令、视图、web app、skills 等，并声明必需/可选权限，宿主逐调用执行 capability gate。没有证据表明该格式与 Codex 插件格式兼容。它定位于工作区 coding harness；核查材料未见 Paperclip 式岗位组织、预算治理或企业任务看板。见 [`manifest.ts`](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/src/shared/plugin/manifest.ts#L290-L401)、[plugin API](https://github.com/AIDotNet/NextCoWork/tree/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/packages/plugin-api) 与 [README](https://github.com/AIDotNet/NextCoWork/blob/b9f580a6c7dadf5ee37e8f1d7e7c09d10a07b917/README.md#L227-L243)。

## Tencent/WeKnora — 知识库、RAG、Agent 与 Wiki

核查提交：[6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6](https://github.com/Tencent/WeKnora/commit/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6)；[MIT LICENSE](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/LICENSE)。

1. **产品边界（官方声明）**：主轴是文档理解、语义检索、知识问答、ReAct Agent 和自动 Wiki。Agent 能用知识检索、MCP、技能与浏览器工具；这不等于岗位汇报树或 Paperclip 式任务认领/预算治理。README 的架构说明为 Go 后端，并含独立 `docreader` 解析服务；不是 .NET 实现。见 [README overview/features](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/README.md#L41-L61) 与 [介绍文档](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/01-getting-started/01-introduction.md)。
2. **知识库模型和管理（官方文档）**：知识库可为 document/FAQ/wiki 类型，各自保存模型、解析器规则、分块、索引和图谱设置；文档有状态、文件夹与标签。UI 可查看解析时间线和失败阶段、停止或重试，编辑分块并保留版本/回滚记录。见 [知识库与知识管理](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/02-knowledge-base.md#L33-L55)、[分块版本](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/02-knowledge-base.md#L88-L101) 与 [KB 配置类型](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/02-knowledge-base.md#L124-L176)。
3. **解析管道（源码）**：Go 侧提供 parser engine registry，可注册本地解析引擎，也会从 Python `docreader` 发现远端引擎；按文件类型规则选引擎。可选 anydoc 用 Rust 静态库经 cgo 集成，但只有带 `anydoc` build tag 的构建才链接，默认构建可不含它。见 [`engine_registry.go`](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/internal/infrastructure/docparser/engine_registry.go#L11-L100) 与 [`anydoc.go`](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/internal/infrastructure/docparser/anydoc/anydoc.go#L1-L8)。
4. **分块与检索（源码 + 官方文档）**：分块支持 legacy/auto/heading/heuristic/recursive 及 parent-child；混合检索将关键词与向量检索分开执行，再用可调权重 RRF 融合，之后可 rerank。检索后端有各自能力边界：例如 ES7 只声明关键词支持，Qdrant 的关键词命中没有 BM25 分数。见 [chunker strategy](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/internal/infrastructure/chunker/strategy.go#L267-L311)、[检索引擎文档](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/05-retrieval-engines.md#L22-L45) 与 [RRF 参数](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/internal/types/retrieval_config.go#L14-L37)。
5. **SQLite 的准确含义**：检索引擎文档列出 SQLite + sqlite-vec + FTS5，定位为桌面、开发和微型部署选项；这证明 SQLite 是可选检索/索引后端，不证明 WeKnora 全部数据都以 SQLite 为唯一事实源。该文档还要求切换检索引擎时重建索引。见 [检索后端选择与能力矩阵](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/05-retrieval-engines.md#L3-L14) 与 [SQLite 行](https://github.com/Tencent/WeKnora/blob/6c3730a6adfd9e77e3472c3f0e3d10fcd805bda6/website-docs/03-features/05-retrieval-engines.md#L24-L37)。

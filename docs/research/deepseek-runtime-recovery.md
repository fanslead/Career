# DeepSeek Harness 运行时、记忆与恢复机制

## 范围与版本

本文只读检查 `deepseek-ai/deepseek-harness` 上游源码，固定在提交 `d743267388641bc76f17c45ce8b4c231aed1d32c`。聚焦 agent loop、模型适配、子 agent、会话和记忆持久化、工具审批、取消及重启恢复。引用均为该提交的 GitHub 源码行号。没有安装依赖、运行测试或修改上游项目代码。

这是运行时层证据，不判断浏览器路由、WebSocket/SSE 重连、前端待审批卡片如何重建；这些行为须以 Web 层调用链另行核对。下文把源码直接显示的行为与从调用边界推导的结论分开标注。

## 结论

Harness 把对话建模为**按序追加的 Session 事件日志**。agent loop 从日志投影出模型历史，在 turn/step 边界运行模型与工具；可选持久化后端保存日志，恢复时读取日志并合成关闭事件。进程重启会创建新的 Agent/loop 生命周期，关闭中断 turn 后从已保存历史发起后续请求；它不会接着消费之前的模型流或自动重放工具。已记录调用但没有结果时，恢复会标注“结果未知”，提醒先检查外部状态。

关键能力是可重建的会话、工具调用配对和有界故障关闭。源码没有显示一个独立的语义记忆库负责把事实跨 Session 自动沉淀、检索和更新；本次检查到的上下文主要来自 Session 历史、工作区指令文件和显式压缩摘要。此判断仅限本文审查的相关运行时和上下文模块。

## 调用链一：一次普通 Agent turn

1. `followup()` 将用户消息放入 Agent inbox 并唤醒 driver。driver 开始 `turn/start`，在每个 `step/start` 前认领输入，装配提示词与工具并执行 `agent/pre-step`。空输入或预处理拒绝可在不调用模型的情况下结束 turn。[agent.ts:154-180](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L154-L180) [agent.ts:252-287](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L252-L287) [agent.ts:297-358](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L297-L358)
2. 每一步经 `agent/request` waterfall 解析 provider/model，再调用 `llm.prepareCall()`。loop 记录规范化的 `request/header`、必要的 `request/context`，从 Session 派生并冻结请求消息。prepared call 把这一请求绑定到确定的 adapter；运行中的配置变更影响后续步骤，不会改写当前模型调用。[agent.ts:400-442](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L400-L442) [agent.ts:563-613](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L563-L613) [agent.ts:615-695](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L615-L695)
3. model adapter 把 provider-neutral 请求转换成具体协议并将 signal 传给传输层。以 DeepSeek adapter 为例，它把 `AbortSignal` 与消费端 signal 合并，序列化 Messages 请求、读取 SSE，并翻译为统一 stream chunks；原生 reasoning 签名以 replay state 随已提交 assistant message 保存，只有适用于同一模型时才复用。[adapter.ts:43-74](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/llm/llm-deepseek/src/adapter.ts#L43-L74) [adapter.ts:77-152](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/llm/llm-deepseek/src/adapter.ts#L77-L152) [replay.ts:29-64](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/llm/llm-deepseek/src/replay.ts#L29-L64)
4. 当前 assistant stream 的 start/chunk/end 帧按 Agent 实例的进程内 revision 发布。完整流结束或中断时，loop 才将 compact stream 连同 assistant message/attempt 一起追加到 Session；中断且已有可见前缀时会追加 `interrupted: true` 的 assistant message。流尚未到达结算点时，单独的实时帧不是 Session 恢复记录。[assistant-stream.ts:17-27](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/assistant-stream.ts#L17-L27) [assistant-stream.ts:48-109](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/assistant-stream.ts#L48-L109) [agent.ts:443-502](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L443-L502)
5. assistant message 含工具调用时，scheduler 先追加 `tool/call`，再进入工具准备、策略审批与 dispatch；并行安全调用可并行执行，结果按模型原始顺序写为 `tool/result`。完成后进入下一 step 或写入 `turn/end`。[tool-calls.ts:60-102](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/tool-calls.ts#L60-L102) [tool-calls.ts:146-247](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/tool-calls.ts#L146-L247) [tool-calls.ts:262-290](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/tool-calls.ts#L262-L290)

## 调用链二：持久化会话的进程重启

1. AgentLoop resume 首先 `persistence.open(id, 'write')`，以单写者所有权排除同一 Session 的并发恢复；随后从 handle 读取物理有效日志。[index.ts:843-883](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/index.ts#L843-L883)
2. 如果日志尾部停在未关闭的 turn，恢复代码调用 `interruptedTurnClosers()`，将缺失 tool result、必要的 `step/end` 以及 `turn/end {kind: interrupted}` 作为普通事件经同一个写 handle 追加，再用该日志准备 Session 并发布一个新的 Agent 生命周期。[index.ts:884-918](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/index.ts#L884-L918) [repair.ts:43-97](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/repair.ts#L43-L97)
3. 已提交的 `assistant/message` 中每个尚未配对的工具调用会得到合成 error result。若此前有 `tool/call` 事件，错误码为 `TOOL_OUTCOME_UNKNOWN`；若没有该事件，错误码为 `TOOL_NOT_STARTED`。恢复器会先关闭未配对工具，再关闭 step/turn；它没有调用原工具的重试逻辑。[repair.ts:100-149](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/repair.ts#L100-L149) [repair.ts:151-210](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/repair.ts#L151-L210)
4. resume 会在新 Agent 实例首次请求时记录 `request/header`，原因是 `resume`，然后从已派生的会话消息构造请求。恢复的是已记录的交谈上下文，不是旧进程的 AbortController、SDK iterator、线程栈或外部工具调用。[agent.ts:110-120](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L110-L120) [agent.ts:635-650](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L635-L650)

**进程重启与界面刷新必须分开看。** 进程重启走上述持久化读取和语义修复；若没有挂载 persistence，Session 是内存态，进程退出后无法按此路径恢复。界面刷新本身不会创建新 Agent，也不会让服务端工具执行停止或重启。服务仍活着时，刷新属于客户端重新订阅/查询；前端能否补齐断线期间的实时流由 Web 传输层决定。runtime 源码能确认已提交 Session 事件可重放，而未结算 assistant chunks 是进程内帧；不能据此声称每个流帧都能在刷新后补回。[agent-loop README:114-116](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/README.md#L114-L116) [agent-loop README:120](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/README.md#L120) [assistant-stream.ts:17-27](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/assistant-stream.ts#L17-L27)

## 调用链三：本地可续接子 Agent

本地子 Agent 有独立 Session，可由 parent 发送消息继续执行。Manager 的 `resident` 激活表是进程内 Map；若 child 当前不 resident，direct parent 的送信路径会查询持久化 child session、验证其 parent lineage，并从 child 日志折叠出 `continuable` descriptor。descriptor 存在时 Manager 调用 `agents.resume()` 重建 child，恢复已保存的 provider/model、reasoning effort、persona、tool filter 等，再把新消息放入子 Agent inbox。fresh create 时写入的 descriptor 和委派策略在 cold resume 时从日志重放，不会再次从父进程采集。[manager.ts:129-147](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent/src/manager.ts#L129-L147) [manager.ts:879-919](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent/src/manager.ts#L879-L919) [manager.ts:1242-1277](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent/src/manager.ts#L1242-L1277) [manager.ts:1321-1376](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent/src/manager.ts#L1321-L1376)

这是**按消息触发的 cold resume**，不是启动时自动重建所有正在运行的 child。它需要 parent Agent live、child session 可读、descriptor 支持 continuable，并依赖 session-query 与 persistence。外部 subagent 则由 activation 持有外部运行句柄；`subagent-dsh-sdk` 启动独立 harness/child runtime，生成私有 session id 并提交 prompt，Manager 的 resident/句柄并不作为 parent 的 durable 子进程目录。[manager.ts:535-544](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent/src/manager.ts#L535-L544) [run.ts:231-250](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent-dsh-sdk/src/run.ts#L231-L250) [run.ts:296-375](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/subagent/subagent-dsh-sdk/src/run.ts#L296-L375)

## 记忆、历史与上下文分别是什么

- **Session event log（持久历史）**：有序、追加的事实记录。它包含模型可见消息，也可以包含 turn/step 边界、请求头、失败尝试、工具调用、审批审计和插件记录。日志并不等于模型每次收到的对话全文。Session append 记录序号与 surface 操作；持久化 write handle 负责路由和落盘。[session persistence README:28, 49, 55-61](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-persistence/README.md#L28-L61)
- **Derived conversation history（模型历史）**：从 `system/message`、`developer/message`、`user/message`、`assistant/message` 和 `tool/result` 等 surface 事件派生。turn/step 边界、`assistant/attempt` 和其他 log-only 事件不会成为模型消息；嵌入的 assistant stream 属于诊断/重放资料。[surface.ts:120-151](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/surface.ts#L120-L151) [session README:125-131](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/README.md#L125-L131)
- **Workspace instruction context（外部工作区记忆）**：AGENTS.md/CLAUDE.md 指令在适用时读取，作为带来源的 user message 放入 Session；文件成功读取/编辑后按目录触达重新对账，resume 时重新对账 baseline。消息已经进入 Session 后会跟随历史重放，但源文件变更也可能让 context 被替换或删除。[agent-instructions README:10-12, 28-40, 86-103](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/context/agent-instructions/README.md#L10-L12) [index.ts:86-103](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/context/agent-instructions/src/index.ts#L86-L103)
- **Compaction summary（压缩后的检查点）**：模型总结一段旧对话，将 summary message 放回 Session surface 并保留近期原文；被替换的 surface 范围不再作为当前模型历史，但底层 append-only 事件仍在日志中。它节省上下文窗口，语义上仍属于该 Session 的历史压缩，不是跨 Session 自动积累/检索的长期事实库。[compaction README:80-86](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/compaction/compaction-basic/README.md#L80-L86) [session README:163-171](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/README.md#L163-L171)

## 工具授权、审批与取消

一次工具调用先经过 `tools/pre-execute` policy waterfall 和单调 deny guards。若结果为 `ask`，runtime 通过 `ctx.approval.request()` 交给审批服务；仅 `allowed-once` 继续 dispatch，rejected、cancelled 或 unavailable 都拒绝该调用。缺少审批服务或 agent identity 时 fail closed。审批 grant 是这一次执行的短期决定；日志中的 `approval/policy` 可保存 Session policy，但 `allowed-once` 不是可供未来调用继承的常驻权限。[tools README:109, 141](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/tools/README.md#L109) [tools.ts:1499-1545](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/tools/src/index.ts#L1499-L1545) [tools.ts:1722-1773](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/tools/src/index.ts#L1722-L1773) [index.ts:30-75, 215-233](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/index.ts#L30-L75) [index.ts:215-233](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/index.ts#L215-L233)

`approval/asked` 与 `approval/decided` 是只供审计/重放的 log-only 事件；请求在本进程中 await answerer，再追加决定。已检查的通用 interrupted-turn recovery 只追踪 tool-call/result 与 turn/step，没有重建审批 answerer 的执行 promise，也没有为孤立 `approval/asked` 合成决定。**源码未证明审批弹窗/待处理请求会如何跨 Web 刷新恢复或在进程重启后重新呈现**；不能把审计记录当作可恢复的审批队列。[types.ts:34-59](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/types.ts#L34-L59) [index.ts:215-233](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/interaction/user-approval/src/index.ts#L215-L233) [repair.ts:100-149](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/repair.ts#L100-L149)

`Agent.cancel()` 通过 AbortController 停止当前活动并默认清除待处理 inbox；`keepInbox` 会保留未认领工作。模型 stream 收到取消时会尽力结算已交付前缀并标为 interrupted。工具调度停止新派发、等待已启动 dispatch settle，再按顺序写结果；未启动的模型工具调用写入合成的 `ABORTED_BEFORE_DISPATCH` 结果。[agent.ts:175-181](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L175-L181) [agent.ts:463-503](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/agent.ts#L463-L503) [tool-calls.ts:216-259](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent-loop/src/tool-calls.ts#L216-L259) [agent README:45-47](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/agent/README.md#L45-L47)

## 持久化屏障与副作用未知边界

- **启用 `session-checkpoint-policy` 时**，模型请求发出前 flush 其请求前缀；顶层工具 body 执行前 flush 已记录的 tool call；下一次 `agent/pre-step` 前 flush 前一步已提交的模型响应和有序工具结果。flush 失败时模型 adapter/tool body 不运行。这是代码能证明的关键副作用屏障；嵌套 dispatch 复用外层调用的 checkpoint。[checkpoint-policy README:46-52, 64-66](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-checkpoint-policy/README.md#L46-L52) [index.ts:63-82](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-checkpoint-policy/src/index.ts#L63-L82)
- **未启用该策略时**，session event 进入 live-event batching。通用 persistence contract 指出 append 是 best-effort，只有 resolved flush 是对 crash survival 的承诺；通用 backend 可在缓冲区内遗失事件。故若有外部副作用发生而对应 tool-call/result 还没落入 durable log，恢复日志本身不足以证明工具是否已经运行。已提供 JSONL backend 的物理 batch 写入会 fsync，但 agent live-event 路径仍由持久化服务的 batching/flush 边界控制，不能仅凭选择 JSONL 推断每个内存 append 已越过 flush barrier。[persistence README:49, 55-61](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-persistence/README.md#L49-L61) [storage.ts:294-343](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-persistence-jsonl/src/storage.ts#L294-L343) [JSONL README:74-76](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/session/session-persistence-jsonl/README.md#L74-L76)
- `tool/call` 已持久、`tool/result` 缺失时，正确解释是**已启动记录存在，真实外部效果未知**，而不是“肯定没做”或“可以直接重试”。恢复文字只允许基于语义安全地重试只读/幂等操作；可能有副作用的操作须先核验外部系统状态或向用户确认。[repair.ts:32-40](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/src/repair.ts#L32-L40) [session README:167-171](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/core/session/README.md#L167-L171)

## 从本次源码仍不能确认的项目

1. Web 刷新后怎样重订阅、回放 missed stream chunks、恢复审批卡片：须检查 Web bridge / client projection；本报告只确认 runtime 中 stream frames 的进程内生命周期。
2. 外部系统的幂等键、补偿事务及各工具实际副作用：由具体工具实现决定，通用恢复器不会猜测或自动重做。
3. 无 checkpoint policy 且使用其他 backend 时，具体 batch window、append durability 与机器断电语义：需按实际部署 backend 验证。
4. 外部 subprocess 类型的 subagent 进程若宿主硬崩后如何发现/终止孤儿进程：Manager 提供启动和正常 teardown 链路，本次未找到跨宿主重启的持久 activation/reaper 协议。

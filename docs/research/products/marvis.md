# Marvis：预设分工、本地资料与操作进度

核查日期：2026-10-14。通过官方公开文档读取产品说明；没有安装、登录、授权本机文件或执行实际任务。下文全部产品能力属于**官方声明**，内部调度、数据流和安全性未经源码或运行验证。

## 定位与默认体验

Marvis 以电脑中的文件和日常任务为入口，强调查找、理解、整理资料和调用工具。它对本项目最有价值的启发，是让普通用户描述结果，再由产品安排执行能力，而不是要求用户理解 Agent、MCP 和上下文窗口后才开始。[产品说明](https://marvis.qq.com/docs/product-description)

## 路径一：一句需求 → 专项分工 → 查看结果

官方 Agent 体系为一个主 Agent 加五个专项 Agent，分工覆盖 File、Computer、App、Browser、Search。主 Agent 自动安排协作；执行视图展示步骤、负责方、中间结果和结果位置。文档提及 MCP、CLI 和 Skill 扩展。[Agent 体系](https://marvis.qq.com/docs/agent-system)

**设计判断：** 默认先提供少量清楚的能力分工，复杂度留在内部。用户的“岗位”更接近业务责任，File/Browser 则是执行能力；不能用几个工具 Agent 名字代替运营、研发、财务等长期岗位。

**未证实：** 并行写入是否真正隔离、主 Agent 如何处理子任务失败、重启后任务如何重新认领、工具运行采用何种进程与协议。页面所称协调能力不等于已验证的冲突控制。

## 路径二：本地检索 → 内容理解 → 文件操作

官方场景把语义找文件、内容识别和整理成文档/表格等后续工作连起来；应用操作取决于已经接入或授权的能力。其风险分级说明要求修改、删除等动作先展示方案，涉及支付的步骤保留人工处理。[核心能力与场景](https://marvis.qq.com/docs/core-ability-and-major-user-scene)

**设计判断：** 搜索结果应能继续进入执行任务。用户看到的是找到哪些资料、将做哪些修改、最后生成什么；确认页需要具体文件与动作，而非笼统的“是否允许 Agent 工作”。这适用于首版文件、网页、终端工具，无须提前扩展任意桌面点击。

## 本地与云端不是一个开关

官方区分本地处理模式和端云协作模式：本地索引、内容识别及部分推理可留在本机，但联网搜索仍需网络；性能优先路径会使用云端能力。内容识别授权与文件名级检索有区别，用户可排除目录，初次索引也有资源消耗说明。[数据与安全](https://marvis.qq.com/docs/data-and-security)

**设计判断：** 本项目设置页至少应分别说明：文件存在哪里、索引在哪里、哪些内容会发给模型、工具能访问哪些范围。仅标“本地部署”无法回答后两项；离线可用也须按任务和模型逐项验证。

手机版轻量使用与连接电脑执行应分别说明；本次没有把手机能访问产品推断为电脑关机后仍能操作本地文件。[产品说明](https://marvis.qq.com/docs/product-description)、[场景说明](https://marvis.qq.com/docs/core-ability-and-major-user-scene)

## 覆盖范围与待查项

| 本需求 | 本次证据能支持什么 | 仍缺什么 |
| --- | --- | --- |
| 多 Agent | 预设角色和自动分工的产品表达 | 持久岗位、招聘/停岗、长期任务归属的运行证据 |

## 对本项目的取舍

建议借鉴：少配置的首次任务；预设分工；执行进度与产物一起展示；文件检索后继续处理；可理解的本地/云端边界。

不照搬：把通用电脑自动化列为首版硬条件；把产品宣称的“不冲突”或“隐私安全”当作验收证据；为模仿预设 Agent 数量而增加运行成本。

下一轮可用同一批普通文件测：首次索引成本、中文模糊查找准确率、排除目录是否真的不进入索引、删除确认是否列出影响对象、拒绝后能否继续其他步骤、重启时是否保留进度。若测端云边界，还需明确选择的模式并检查实际网络请求。本次均未执行。

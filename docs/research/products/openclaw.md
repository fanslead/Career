# OpenClaw 产品与 harness 核查

核查日期：2026-10-14。固定上游提交：[`da6adccf7dba01914083e8f2b55116c1d02b05c8`](https://github.com/openclaw/openclaw/commit/da6adccf7dba01914083e8f2b55116c1d02b05c8)（2026-10-14）。源码链接均固定到此提交并标注行号。研究只读查看上游源码和官方文档，未安装、运行或登录上游项目。

下文将实现路径标为“源码确认”，仓库说明标为“官方文档自述”。这些不是运行结果；对未执行的行为不作实测结论。

## 产品定位

**官方 README 自述：** OpenClaw 是运行在用户设备上的开源 AI 助手，通过用户已有的聊天渠道和原生应用提供服务；一个 Gateway 可用于个人或团队部署。仓库也把模型和 agent harness 描述为可替换插件。[README 定位与运行边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/README.md#L1-L22)

**源码结构确认：** Gateway 的 `agent` 请求经 admission、会话准备和异步执行进入嵌入式 agent runner；回传事件与终态由单独接口处理。因此这里研究的是一个多渠道 Gateway 产品中内嵌的 agent harness，不是独立桌面聊天循环。[Gateway `agent` handler](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/server-methods/agent-run-handler.ts#L17-L85) [异步运行分派](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-turn-service.ts#L508-L571)

## 用户流程一：从请求到工具结果和终态

**源码确认：** Gateway handler 校验请求、获取当前调用者权限并执行 preflight，然后调用 `startTurn`。[入口及 preflight](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/server-methods/agent-run-handler.ts#L17-L78) `agent-turn-service` 解析消息和会话目标，持久化/绑定会话条目，准备 dispatch 后启动 `startAgentRunExecution`；执行通过 Gateway admission、abort controller 和 session 身份继续。[会话准备与持久化调用](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-turn-service.ts#L156-L205) [会话提交](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-turn-service.ts#L415-L469) [异步执行交接](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-turn-service.ts#L508-L571)

**源码确认：** attempt 准备阶段由 `createAgentSession` 构造运行会话，传入已选模型、内建工具 allowlist、custom tools、会话管理器和资源加载器；deferred 工具只在请求解析时加载。该 session 使用仓库自有 `packages/agent-core`，`Agent.prompt` 调用 `runAgentLoop`。[AgentSession 与工具 loadout](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/embedded-agent-runner/run/attempt-session-prepare.ts#L155-L220) [仓库自有 runtime adapter](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/plugin-sdk/agent-core.ts#L1-L29) [prompt 到 agent loop](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent.ts#L480-L495) [loop 调用模型与工具分派](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent-loop.ts#L273-L302)

**源码确认：** model tool call 按名称解析为允许的工具或已授权的 deferred tool，校验参数并运行 `beforeToolCall`；通过后才调用工具实现并发出 tool start/update/end。tool result 接入后 loop 根据 stop/continuation 决定继续请求或结束 agent turn；`Agent` 收到 `agent_end` 后等待 listener 完成再清理 active run。[解析、验证和拦截](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent-loop.ts#L926-L1046) [工具执行](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent-loop.ts#L1153-L1169) [工具 start/end 事件](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent-loop.ts#L1371-L1400) [tool result 与下一轮/终止](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent-loop.ts#L329-L364) [run idle 等待 listener 收束](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/agent-core/src/agent.ts#L679-L695)

**官方文档自述 + 源码确认：** 工具 start/update/end 作为 `tool` stream，assistant delta 和生命周期分别作为 `assistant`/`lifecycle`；事件订阅器给事件加 transcript 起始锚点后转给 run observer。`agent.wait` 对 `runId` 返回 `ok`、`error` 或 `timeout` 等终态。[事件类型和 wait 合同](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/agent-loop.md#L18-L24) [事件订阅桥](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/embedded-agent-subscribe.ts#L53-L75)

**流程边界：** 本仓库源码确认 OpenClaw 组装了模型、工具和 `AgentSession`，并调用 `prompt`；不在此处声称某个 provider 的网络请求或外部工具效果已经实测。Gateway 流程说明和源代码追踪互相补足，不等于端到端运行证据。

## 用户流程二：持久化、取消、压缩和恢复

**源码确认：** Gateway 为用户输入构造带 run-scoped idempotency key 的 `UserTurnInput`，创建 transcript recorder，并须通过 `stageApproved` 才算 durable admission；被停止的输入会以 `cancelled` 或 `interrupted` 收束。[输入记录与 durable admission](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-run-user-turn.ts#L267-L361) [停止时收束 pending input](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-run-user-turn.ts#L471-L500) SessionManager 将 message 和 transcript event 交给 SQLite transcript append/worker；写入会检查 session binding 与当前 writer claim，compaction entry 走专门持久化事务。[SQLite transcript append 路径](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/sessions/session-manager-append.ts#L73-L110) [writer fence 与 compaction commit](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/sessions/session-manager-persistence.ts#L64-L128)

**官方文档自述：** 每个 agent 的会话历史存于 `<agentDir>/openclaw-agent.sqlite`。默认自动压缩把旧轮次总结为 transcript entry、保留近期消息；完整历史留在磁盘。若工具结果已经 settled 后 provider 报上下文溢出，内建 runtime 可以压缩后继续且不重放已完成动作；pending tool、审批、取消等不满足该恢复条件。Gateway 重启打断这类续跑时，文档称已接纳输入仍会保留。[每 agent 的 SQLite 会话库](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/multi-agent.md#L9-L23) [压缩和溢出恢复合同](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/compaction.md#L9-L21) [已完成工具后的恢复边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/compaction.md#L59-L84)

输入状态也能从 session history 的 `pendingInputs` 中区分：`queued`、`cancelled`、`interrupted`。取消的输入不会自动运行；interrupted 输入保留供检查，只有满足特定 peer-delivery ownership 条件的普通消息才可能被 Gateway 重接纳。[pending input 对用户可见的状态语义](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/session-tool.md#L85-L99) `agent.wait` 的源码区分仍在排队和已经完成/超时的观察结果。[等待 run 终态](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-wait.ts#L13-L70)

## 模型、Skills、MCP 与插件边界

- **模型配置（源码确认 + 官方文档）：** `models.providers` 可配置 provider 的 `baseUrl`、密钥、API adapter 和模型目录；模型也可覆盖 adapter/base URL。仓库定义了多个协议 adapter ID，包括 OpenAI Completions/Responses、Anthropic Messages、Google Generative AI、Bedrock Converse Stream、Ollama 等。`compat` 元数据可以控制 payload shaping 或能力门控，但文档要求自定义 endpoint 的兼容能力在声明前先核实；配置 adapter 类型本身不证明任意代理完全兼容。[adapter ID](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/packages/llm-core/src/model-data.ts#L1-L15) [provider 与 model schema](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/config/zod-schema.core.ts#L246-L280) [自定义路由能力说明](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/model-providers/custom-providers.md#L10-L24)
- **Skills（官方文档）：** Skills 是可从 workspace、agent、shared、extra 和 plugin roots 发现的技能资源，可由 agent allowlist 限制可见集合。技能位置、prompt 可见性和运行时工具策略是分开的；allowlist 不等同于文件/进程授权。workspace 默认 cwd 也不是硬隔离，sandbox 需另行配置。[共享与 agent 级技能范围](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/skills.md#L121-L141) [allowlist 是可见性控制](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/skills.md#L224-L255) [tool policy 仍单独生效](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/session-tool.md#L37-L39) [workspace 不是硬 sandbox](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/multi-agent.md#L44-L46)
- **MCP（官方文档）：** `openclaw mcp serve` 把 OpenClaw Gateway 会话暴露给外部 MCP client；其他 MCP 命令管理 OpenClaw 可供 agent runtime 消费的出站 server。`status`/`doctor` 读配置，`probe` 才主动建立连接。外部 MCP 工具还受 OpenClaw 的 tool profile/policy 约束，连接本身不会绕过授权。[MCP 双向角色和探测差异](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/cli/mcp.md#L11-L36) [MCP 工具受相同策略约束](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/mcp.md#L10-L39)
- **Native plugins（官方文档）：** 插件可注册模型 provider、embedding、channel、speech、web、media 等 capability，也可提供 hooks 或 tools。项目明确将 capability 注册视为发展方向，同时说明对外插件兼容面仍在收紧，不能把每个 export/helper 都视为冻结 ABI。[native capability 注册与对外兼容边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/plugins/architecture.md#L32-L69)

这三层含义不同：Skills 提供技能资源/指令，MCP 接入独立 server 的工具，native plugin 在 OpenClaw runtime 注册扩展能力。不要把其中任一层等同于操作系统隔离或用户确认。

## 记忆、隔离、subagent 与可见状态

- **记忆和 session scope（官方文档）：** `USER.md`、`MEMORY.md` 和按日 Markdown notes 放在 agent workspace；另有每 agent `agentDir` 和 SQLite-backed session history。多 agent 可共享明确配置的 skills roots，但 plugin 自有存储不一定随 agent 拆分；workspace 又不是文件系统边界。[workspace Markdown memory](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/memory.md#L9-L30) [agent-owned workspace/state/session store](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/multi-agent.md#L15-L23) [plugin store 与 workspace 边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/multi-agent.md#L37-L46)
- **Subagent（官方文档 + 源码确认）：** `sessions_spawn` 为后台工作创建独立子 session，默认有独立上下文和 token 成本；父 transcript 默认不共享，需要时可选择 `context: "fork"`，thread-bound session 默认采用 fork。源码先解析目标/模式、创建 child session 和准备 spawn context，再据 completion mode 建立结果交接。[子 agent 上下文与默认行为](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/subagents.md#L12-L32) [spawn 输入解析与 child session](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/subagents/spawn/subagent-spawn.ts#L68-L114) [结果交付模式](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/subagents/spawn/subagent-spawn.ts#L297-L325)
- **用户可见状态（官方文档）：** Gateway 可流式显示 assistant/tool/lifecycle 状态并由 `agent.wait` 等到 run 终态；Control UI 的 Subagents 面板分 Running/Finished 展示 child，允许打开 view-only transcript 并返回父任务。`sessions_list`/`session_status` 提供状态和 session 操作工具，但最终是否出现仍受 tool profile、sandbox 和 agent policy 控制。[Subagents 面板行为](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/subagents.md#L35-L45) [可用 session/status 工具](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/session-tool.md#L20-L39)

## 可借鉴与不宜照搬

**可借鉴：**

1. 用稳定的 `runId` 区分接纳与终态，提供事件流和独立 wait 结果；调用者不需要靠轮询生成文本推测任务是否结束。[Agent loop 运行合同](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/agent-loop.md#L18-L24)
2. 对 transcript 写入做 writer ownership/fencing，阻止旧 run 在新 run 接管后提交过时上下文。[writer claim](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/agent-loop.md#L54-L66)
3. 分开配置 memory/workspace、skill 发现范围、模型 API adapter 和实际 tool policy；把这些可见性/路由机制与执行隔离分别呈现给用户。[Skills 与 allowlist](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/skills.md#L121-L141) [工具策略](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/session-tool.md#L37-L39)

**不宜照搬：**

1. OpenClaw 覆盖许多聊天渠道、原生客户端、插件能力和 agent runtime；这是个人/团队 Gateway 的产品范围。对较窄的交互 harness，照搬整套渠道/插件表面会增加状态和支持成本。此项是基于产品定位的取舍建议，不是上游缺陷判断。[README 产品范围](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/README.md#L18-L22) [plugin capability 面](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/plugins/architecture.md#L32-L56)
2. 不要把 workspace 路径、skill allowlist 或 subagent 的独立 session 当成强安全隔离。上游文档明确说 workspace 不是硬 sandbox，技能 allowlist 只做可见性过滤，隔离需要实际 sandbox/tool policy。[workspace 边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/multi-agent.md#L44-L46) [技能 allowlist 边界](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/tools/skills.md#L224-L255)

## 可复现的后续验收（本次未执行）

1. 用确定性测试 provider 返回“工具调用 → 工具结果 → 最终文本”，经 Gateway `agent` 触发；断言同一个 runId 的 stream 顺序包含 lifecycle start、tool start/update/end、assistant 最终 delta、lifecycle end，随后 `agent.wait` 返回终态。再测试错误 schema、取消和超时，确认错误状态与 transcript 收束一致。
2. 给一个 Gateway 输入相同 runId/request identity 注入故障，检查 recorder 的 idempotency、`queued/cancelled/interrupted` 状态；并发运行同 session 的两个请求，确认旧 `activeWriterRunId` 无法覆写新 transcript。[用户输入 recorder](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/gateway/agent-turn/agent-run-user-turn.ts#L267-L361) [Session writer fence](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/src/agents/sessions/session-manager-persistence.ts#L64-L128)
3. 让 fake provider 在已成功的工具结果之后返回 context-overflow，再启动 Gateway restart；检查 compaction summary 与近期 transcript、输入 custody 是否保留，且已完成工具没有再次产生副作用。另用 pending approval/cancel 对照，确保不走 settled-tool replay 分支。[恢复前提和排除项](https://github.com/openclaw/openclaw/blob/da6adccf7dba01914083e8f2b55116c1d02b05c8/docs/concepts/compaction.md#L74-L84)
4. 配两个 agent，分别只授予不同 workspace skills，并共享一个显式 shared root；检查加载快照、allowlist、memory files/session DB 的范围，再 spawn 一个默认 child 和一个 `context: "fork"` child，对比其上下文和 UI Running/Finished/announce 状态。测试时分别启用 sandbox 和关闭 sandbox，以验证 workspace/skill 可见性不是访问授权。

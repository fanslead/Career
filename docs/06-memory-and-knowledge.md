# 记忆、岗位经验与知识库

更新：2026-10-14。根据产品研究重写的设计基线，尚未实现或通过运行验收。配置、已发布记忆与知识原件以文件为权威；对话、运行状态和未发布候选以 SQLite 为权威。恢复合同见 [13](13-restart-and-recovery.md)。

## 1. 先分清四种内容

| 内容 | 解决的问题 | 权威位置 | 能否直接作为长期事实 |
| --- | --- | --- | --- |
| 工作上下文 | 这次正在做什么、等谁、哪些工具已完成 | 消息、Run checkpoint 与操作账本，`app.db` | 否；不能替代执行账本 |
| 经历记录 | 做过什么、结果如何、哪些方法失败 | 原始对话/任务在 `app.db`；发布后的摘要文件 | 否；摘要是线索，结论要追溯来源 |
| 长期记忆与岗位经验 | 已明确的偏好、适用规则、可复用方法 | 版本化记忆文件及发布清单 | 取决于来源、确认状态、适用范围和时效 |
| 知识资料 | 用户提供或获准引用的原始材料 | `knowledge/` 原件与版本清单 | 作为资料证据，不因检索命中自动变成记忆 |

会话压缩只减少送给模型的历史，不删除原始记录；RAG 检索只选出相关资料，不证明每一条内容正确。记忆不能充当审批、权限或工具已成功的证据。一个条目写“邮件已发”不如 Operation 回执可靠。

## 2. 类型、范围、冷热是三个维度

记忆类型：近期经历 `episode`、长期事实/偏好 `fact`、岗位经验 `experience`。当前工作上下文不进入这套发布目录。

| 作用域 | 默认可见者 | 进入范围的条件 |
| --- | --- | --- |
| 成员私有 AgentPrivate | 本长期成员的获准任务 | 有效成员身份及当前项目允许范围 |
| 项目 Project | 绑定到该项目的任务 | 明确的项目资源绑定 |
| 岗位 Role | 担任该岗位且任务允许使用的成员 | 岗位经验已显式发布，成员绑定该岗位 |
| 工作区 Workspace | 明确绑定共享资料的任务 | 工作区发布规则与任务范围允许 |

同岗位不意味着读取彼此私有记忆；临时子 Agent 默认只收到交接包和获准的共享条目，不复制父成员私有记忆库。需要某条私有结论时，由父任务提供经过范围检查的最小引用或摘要。

冷热是召回策略：Hot 为小量高频且仍适用内容，Warm 按查询检索，Cold 不默认注入但可显式查找。冷热变化只更新条目的访问层级，不移动或复制权威正文；归档相当于转 Cold，撤回或删除是另一个生命周期动作。过期事实不能因最近被访问就重新视为有效。

## 3. 固定文件格式与引用

第一版采用 **JSON 元数据 + 不可变 Markdown 正文版本**，不同时维护 frontmatter 和伴随元数据两种规范：

```text
.memory/facts/<memory-id>/
  entry.json
  versions/1.md
  versions/2.md
```

`episodes`、`experience` 采用同一结构；成员私有内容位于 `.agents/<agent-id>/memory/`。项目和岗位条目仍在共享 `.memory` 中，以 `scopeType/scopeId` 区分，不靠目录层级猜授权。

`entry.json` 记录：稳定 ID、类型、scope、currentVersion、正文 hash、lifecycle、evidenceStatus、accessTier、适用条件、有效期、来源定位、发布/复核者、时间、supersedes/derivedFrom 和 revision。正文版本一经发布不覆盖；同一 ID 的新版本用条件更新切换 currentVersion。

来源定位到 taskRevision、runId、消息水位、已验收 artifactVersion 或知识文件版本/页段。来源被删除、不可读或版本过期时给出明确状态；共享展示不泄露无权读取的来源正文。模型给出的“置信度”只作辅助，不能替代证据。

生命周期为 Candidate（尚在数据库）、Active、Superseded、Revoked、Deleted；冲突或来源待核验用独立 evidenceStatus 表示，并从默认注入排除。Cold 内容仍可 Active，避免把归档、失效与删除混成一个状态。

## 4. 从候选到可用记忆

```mermaid
flowchart LR
  SOURCE[明确指令 / 已提交经历与成果] --> CANDIDATE[数据库候选]
  CANDIDATE --> CHECK[范围、来源、冲突、敏感内容检查]
  CHECK --> DECISION[按发布规则确认]
  DECISION --> FILE[写不可变正文并原子更新清单]
  FILE --> READBACK[重读校验并记录发布完成]
  READBACK --> INDEX[建立派生索引]
  INDEX --> USE[检索时再次核对清单与撤回状态]
```

| 候选来源 | 默认处理 |
| --- | --- |
| 用户明确说“记住这个” | 写入当前明确范围；未指定时限于当前成员/项目，不自动升为全工作区 |
| 已提交任务的低风险经历摘要 | 可自动发布为该成员或项目的经历；只是经历，不宣称普遍结论 |
| 自动提取的偏好或事实推断 | 保持候选，供用户确认/纠正后使用；不悄悄注入其他任务 |
| 有明确证据支持的长期事实 | 可按用户启用的低风险发布规则进入指定范围；关键业务事实仍需明确复核 |
| 已验收任务提炼的方法 | 保存为候选岗位经验；检查输入前提、证据和适用边界后发布 |
| 准备共享的私有条目 | 显式选择目标范围，检查内容与来源可见性；默认由用户或指定发布者确认 |

候选提取使用已提交消息水位，以来源范围、提取器版本和目标范围去重；运行结束、定期整理和用户主动整理可触发同一流程。崩溃后重新提取不能重复发布同一候选。提炼失败不回滚已经完成的业务任务。

Host 是记忆发布入口。DB 先保存发布意图，再写正文版本，原子更新清单，重读校验并提交发布结果。文件清单已更新而数据库未完成时，按 operationId 和 hash 补记，不再生成另一条记忆；冲突文件隔离处理。检索索引落后不改变权威文件，不能让旧索引绕过已生效的撤回。

## 5. 共享、冲突与经验更新

共享的两种动作有不同含义：

- **绑定已发布共享条目**：增加明确资源引用，所有引用者看到同一权威 ID；每个 Run 固定当时版本。
- **将私有结论发布到共享范围**：创建独立共享条目，保留受控 derivedFrom 关系和公开可读的证据摘要；私有条目的后续编辑不自动改共享版。

第二种属于有来源的发布，不是双向同步。共享内容的变更由单一 Host 发布入口串行处理，并比较 expectedRevision；两个成员同时修改时返回冲突与差异，不采用最后写入者覆盖。显式撤回共享版不会删除各成员的原始对话，但阻止继续把它作为共享结论使用。

发现矛盾时，保留双方内容、来源和适用条件，标为 disputed；先判断是否只是时间、地区、项目条件不同。未解决冲突不注入一个看似确定的答案。用户更正或更强证据产生新版本并标记被替代关系，重新生成受影响的摘要和索引。

岗位经验要记录“在哪类输入下验证过、失败条件是什么、引用哪次验收”。一次成功不自动推广为所有项目的做法。可执行技能脚本需要独立的能力发布和工具授权，不能通过记忆发布顺便安装可执行代码。

## 6. 每次运行怎样使用记忆

顺序固定为：校验 scope 与绑定 → 排除未确认、撤回、冲突和过期条目 → 按当前目标与岗位相关性检索 → 核对来源和版本 → 在预算内装配 → 保存 ContextManifest。

ContextManifest 记录实际使用的 memory ID/version、知识 chunk/源版本、会话水位、提取/压缩版本和允许范围；它记录引用而非另一份可编辑事实源。完整 provider 上下文或 checkpoint 可能含文本副本，应纳入保留和删除策略。

Hot 也不代表每轮全量灌入；每次保留用户目标、工具结果和输出预算后，再分配记忆/RAG 预算。历史归档只有在用户询问旧事或相关检索需要时读取。对引用的时效性有疑问时核验，而非只重复旧结论。

运行恢复或长等待结束时重新检查撤回状态、版本和任务范围。普通配置更新可以留待下一 Run；紧急停用、授权撤销和用户要求忘记的内容不能因旧 checkpoint 再次发送。

## 7. 纠正、停用、归档与忘记

| 用户动作 | 实际效果 |
| --- | --- |
| 此次不使用 | 本次上下文排除；不改变全局条目 |
| 纠正 | 发布新版本，旧版本标被替代，关联运行可追溯 |
| 归档 | 转 Cold，不默认召回；仍可主动搜索 |
| 停用/撤回 | 禁止新上下文使用，保留受控记录供追溯 |
| 忘记/删除 | 禁止使用并按用户选择清理正文、索引、摘要、缓存、候选与含副本的检查点 |

忘记命令先持久记录抑制状态，再清理文件和派生数据。查询与上下文装配必须检查抑制状态，不能等待异步重建索引结束才停止使用。记录抑制的 tombstone 不保存已删除正文；是否保留最小 ID/时间审计向用户说明。

活跃请求中已经送给模型的文本无法撤回。系统尝试取消相关在途请求，在下一受控边界停止注入，并丢弃/重建受影响的续接上下文；不能承诺已经生成的外部结果自动消失。若清理 checkpoint 导致不能续跑，应保留任务和成果并明确要求从安全边界新建 Run。

删除来源对话时，列出派生候选/记忆/产物的影响，用户可一并删除，或保留并标“来源已删除”。不能未经说明保留可继续提取正文的隐藏副本，也不能用一条删源动作擅自删除已发送给他人的成果。

备份恢复必须检查比备份更新的删除/撤回记录。能取得最新抑制日志时先应用；若只剩旧备份，无法知道备份之后发生过哪些删除，就先禁用自动记忆注入，提示用户审查恢复范围。不能承诺仅凭旧备份自动识别未来删除。

## 8. 知识库的完整生命周期

原件导入与可检索是不同阶段：保存原件和 documentVersion → 解析 → 分块 → 关键词/向量索引 → 校验 → 发布可检索代次。OCR、摘要等附加处理可独立继续，UI 明示当前可用范围。

首版目标为 Markdown、文本、可提取文本的 PDF 和常见 Office 文档，扫描件使用可选解析器；具体格式需在目标平台验证。保留页码、标题、工作表和行范围；不能只按字符长度切碎表格。

每个 ingestion job 带文档版本、解析配置、indexGeneration、attempt 和取消状态。重解析建立新代次；旧 job 的迟到结果不能切换新代次或让已删文档重新出现。取消只停止后续处理，已存原件/分块是否保留明确显示；删除立即从可用清单排除，再异步清理索引和文件。

更换源文件保留稳定 documentId，新增 documentVersion；旧引用指向当时版本，不默默改指新文件。已有业务引用的旧版按保留策略保存或标不可用。去重以内容 hash 与来源信息判断，不能将同内容的不同授权范围自动合并。

## 9. 检索与 Embedding 迁移

先按项目/成员绑定和有效版本过滤，再分别做 FTS5 关键词与向量召回，融合后可选 rerank，最后依上下文预算提供片段和父段落。引用落到明确文档版本、页/段/表格位置；证据不足时说明，不能只附一个标题。

索引代次保存模型指纹、维度、query/document 前缀、归一化、解析和分块版本。旧 query embedding 与旧索引成对使用；新代次完整生成并验证后切换 activeGeneration。若旧模型不可用，明确降级关键词检索或暂停语义检索，不使用新向量搜索旧空间。

小规模可先用 SQLite 保存向量并做精确相似度检索；扩展索引实现待规模与目标 RID 验证后选择。中文、中英混合、表格、不可回答和冲突问题都需要评测。具体原生扩展与 AOT 支持仍见 [技术证据](research/dotnet-maf-aot-evidence.md)，不是本轮新验证结果。

本地原件不代表本地推理。知识与记忆都记录允许处理范围；仅本地资料不能在本地模型失败时自动发送给云模型或云 Embedding。

## 10. 用户可检查的结果与验收

资料页分为知识库和记忆。记忆显示类型、范围、来源、版本、确认状态、冷热与使用记录；用户可看候选、改错、发布共享、归档或删除。知识库显示处理阶段、失败原因、引用位置、重建进度和当前索引版本。

必须验证：重复提炼不会重复发布；私有经验不串到其他成员；冲突记忆不作为确定事实注入；撤回后新任务和重启恢复都停止使用；旧索引/旧 job 不复活已删资料；共享发布中断可对账；旧备份不会无提示开启记忆；引用能打开准确版本。

本设计吸收 [WeKnora](research/products/weknora.md) 的知识生命周期和候选确认、[WorkBuddy](research/products/workbuddy.md) 的可编辑记忆、[Codex](research/products/codex.md) 的后台提炼边界、[Pi](research/products/pi.md) 的历史与压缩区分。所有本项目行为仍待实现和验收。

[DeepSeek Harness](research/products/deepseek-harness.md)的上下文压缩和第三方 MCP memory 也分属不同能力。外部 memory 工具可以接入，但来源、范围和撤回不能绕过本节合同；连接成功不代表内建长期记忆治理已经完成。

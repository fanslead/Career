# 生产实现任务清单与验收分工

更新：2026-10-15。状态：**分阶段实施中**，首个单所有者本地闭环已交付，实测范围见 [18](18-production-m1-delivery.md)。本文件将 [14 生产级实现方案](14-production-implementation-plan.md) 拆成可独立审查、验证和提交的工作包。表格仍是完整包的目标，不因部分子项实现而整体标记完成；任务包负责人指责任边界。

## 1. 实施规则

每个任务包开始前固定输入合同、文件范围、数据迁移和失败语义；结束时交付可运行行为、用户可见的失败/恢复入口、对应测试和证据。任务包太大时按“创建/查询 → 状态变化 → 恢复 → UI”拆小批，但不能以只有正常路径的演示宣告整个包完成。

Core 状态机、SQL 迁移、Contracts 和恢复规则各设一个集成负责人。并行人员按模块和文件分工，协议改变先更新合同和兼容测试；不同任务不能同时修改同一工作目录或浏览器会话。前端、Worker 适配器、解析器和发布包可以围绕固定合同并行。

生产工程另建，`experiments/p0/` 保留为参照。迁移已有能力时保持旧测试可跑，并为正式模型补充新断言；不把实验 Run/审批表直接扩成全部业务主表，不删除原有失败证据。测试根据风险选择，不为简单展示字段堆重复用例；状态、授权、效果和恢复边界必须有针对性验证。

## 4. 新增安全与发布验收定义

以下全部是待实施验收，当前状态均为**未验证**。

| 编号 | 场景 | 通过判据 |
| --- | --- | --- |
| SEC-01 | 未登录/错误来源、伪造 Host、过期/撤销令牌、SSE 重连与代理头伪造 | API、SSE、成果下载和管理入口一致拒绝；合法配对/登录可恢复；无凭据 URL 与旁路 |
| SEC-02 | 更换 task/artifact/connection ID、使用旧 assignment 或过期批准、有限 API 凭据调用管理命令 | Host 根据对象 scope/revision/current grant 拒绝；没有新增效果；前端隐藏按钮不能替代后端验证 |
| SEC-03 | 路径穿越、符号链接/reparse point、大小写/长路径、检查后替换路径 | 支持平台均不能越出授权资源或触及 vault/主库；受控文件操作验证真实效果而不只验证字符串 |
| SEC-04 | URL/重定向/DNS 重绑定访问私网、回环、元数据端点，MCP/OAuth 恶意元数据 | 每跳和实际连接目标受出口策略约束；显式本地模型例外仅覆盖该连接；没有任意代理与秘密泄漏 |
| SEC-05 | 不可信代码读宿主文件/秘密、逃逸进程树、持续写入、耗尽 CPU/内存或访问未授权网络 | 所声明隔离模式实际阻断；不支持的环境显示不可用；取消/超时后确认停止或冻结资源，不重复派写 |
| SEC-06 | 密钥错配/丢失、刷新重放、配置导出、异常日志和诊断包 | 不覆盖旧凭据库；秘密不泄漏；轮换/撤销有效，恢复需明确凭据材料或重新配置 |
| SEC-07 | Markdown/HTML/SVG/附件脚本、恶意文件名、提示注入要求越权操作 | 不执行同源脚本，不访问未授权秘密/目标；提示注入不能改变服务器策略；危险预览有隔离或下载处理 |
| SEC-08 | 插件/技能/MCP 元数据变更、新工具加入、运行中撤权、权限声明与实际请求不符 | 当前 Run 使用固定能力快照；撤权阻止新派发；旧批准不授权新内容；外部进行中效果进入对账 |
| REL-01 | 全新受支持 OS/CPU 上安装、启动、卸载和重新连接 | 无开发 SDK 依赖；基本功能和可选依赖状态正确；卸载默认保留工作区，删除数据需单独明确动作 |
| REL-02 | 从前一受支持版本升级，迁移/文件更新中断，再尝试回滚 | 无半迁移读写；版本兼容检查有效；不兼容回滚使用一致备份；旧恢复任务/批准不扩大范围 |
| REL-03 | 活跃任务/文件发布期间备份、异机恢复、备份损坏/密钥丢失/旧撤回水位 | manifest 校验完整；主事实/正文/引用一致；失败不覆盖有效工作区；旧备份恢复不自动派发/外发/注入不确定记忆 |
| REL-04 | 发布包被篡改、依赖漏洞/许可证异常、Host/Web/Worker 版本不匹配 | 校验或签名拒绝篡改；保留 SBOM/锁文件/来源；不兼容组件不启动执行；安全问题按可利用性评估，阻塞项修复或取消该能力支持 |

真实断电、真实磁盘满、外部发送和账号授权使用专用隔离资源，开始执行时明确资源范围。对“可能已经发出”的写操作，测试目标应支持查询效果；SMTP 等无可靠查询时验证保留 UnknownOutcome 和停止自动重发。

## 5. 推荐起步批次

先完成一个规模受控的生产基础批次，不同时启动全部 21 个工作包：

1. **合同与目录**：建立正式工程和 W01 最小协议，固定对象身份、状态、错误码、版本与 AOT 检查入口。
2. **工作区与 schema v1**：完成 W02 的初始化/锁/迁移/文件发布基础，配套 W19 的最小一致备份和恢复。
3. **登录与凭据**：完成 W03 的本机配对、所有者会话和一个连接凭据；在实际 AOT 包中验证。
4. **Worker 监管**：完成 W05 的握手、超时、取消和进程归属，模型先使用确定性替身做协议/故障验证。
5. **首个真实任务**：进入 W04/W06/W07/W09/W10，实现“指定资料生成报告 → 固定版本验收”，并通过 W08 的中断恢复。此时只算 M1 内部可用闭环。

步骤 1 固定合同后，存储、身份依赖验证与 Web 基础可并行准备；涉及 schema、授权或状态机的合并顺序由集成负责人控制。M1 稳定后再并行 M2 与 M3，最后补齐外发和发布门槛。

## 6. 每批次交付记录

每批记录任务包/场景 ID、源码 commit、schema/协议/依赖版本、运行平台、功能前后行为、验证命令与原始结果、未决问题和回退方式。用户评审应能直接看到实际成果、失败恢复入口及证据，不必只读实现日志。

现已完成原型及体验审查（16），并建立正式工程及单所有者的任务、审批、成果验收、普通 Worker、会话/凭据和离线备份子项；详情见 [17 合同](17-production-m1-contract.md)、[18 实测记录](18-production-m1-delivery.md)。真实模型/外部服务、完整协作和其他平台尚未验证。工期按工作包完成情况再估算；账号、签名、原生平台与试用资源是对应阶段的外部前置条件，不能把未拿到资源的门槛记为通过。

## 2. 后续追问与当前结论

**NextCoWork 如何通信：** 已查固定 commit 的具体调用链，本机为 Electron IPC，远端设备通道为 WSS，模型供应商流另走 HTTP/SSE。React 不是直接连模型。详见 [源码研究](research/nextcowork-runtime-communication.md)。

**React 与 Electron：** 用户已明确先 React + 独立 .NET 服务，后加 Electron，见 U09 和 [选型讨论](12-react-and-electron.md)。

**深入产品研究：** [九产品比较](research/product-comparison.md)及分产品记录补充了调用链、岗位与子任务区别、产物、知识处理和恢复边界。本文 D01–D18 仍为设计建议，不能把第三方源码存在等同于本项目验证通过。[P0 记录](validation/2026-10-14/p0/README.md)列出当前未完成项。

**DeepSeek Harness：** 固定提交已确认 Web 可独立运行，HTTP RPC + WS 长流，Electron 为另外的壳。实验 Teams 和外部 MCP memory 不能替代本项目的长期岗位、记忆治理与恢复合同。完整研究见 [DeepSeek Harness](research/products/deepseek-harness.md)。

**本轮设计修订：** [04](04-agent-harness-and-projects.md)、[06](06-memory-and-knowledge.md)、[11](11-frontend-runtime-protocol.md)已重写，并新增 [13](13-restart-and-recovery.md)。这些是可供评审的目标合同，不是 P0 实现或验收结果。

**P0 恢复验证：** 两项原始问题已修复；macOS arm64、Linux arm64 与 Linux x64 Docker 本地卷的最终套件各 23/23 通过，浏览器核心交互通过。Linux x64 使用 amd64 仿真；不可靠共享挂载会被启动防线拒绝。配置与剩余门槛以 [实测记录](validation/2026-10-14/p0/README.md)为准，不将受控文件回执验证外推为完整业务恢复。

**P0 复审交付：** U14 授权后修复 Host 来源检查、界面迟到读取/离线操作、窄屏顺序及测试驱动边界；三种配置完整套件再次各 23/23 通过，另有 16 项针对性测试通过。当前证据和本地提交范围以 [复审交付记录](validation/2026-10-14/p0/review-and-delivery.md)为准，未开始完整业务开发。

**生产实现规划：** 按 U15 新增 [14 生产方案](14-production-implementation-plan.md)和[15 工作包](15-production-work-packages.md)，明确正式工程、模块责任、M0–M5 实施批次、21 个工作包和安全/发布验收。新增数值与支持策略是建议默认值；既有完整产品矩阵仍未验证。

**前端原型与体验审查：** 按 U16 新增 [可点击原型](prototype/index.html)、[页面图册](prototype/gallery.html)与 [16 审查记录](16-prototype-and-ux-review.md)。修正查看/处理边界、对象状态隔离、离线可用性、草稿与焦点恢复；当前是本地模拟，未接入生产后端。

**首个正式闭环：** U17/U18 已进入工程实现。macOS arm64 的正式 Host/Worker、SQLite、React、单任务审批与固定版本验收、身份与最小离线备份已通过本地分层验证；真实模型、其他平台、完整工作包仍未放行。见 [17](17-production-m1-contract.md)、[18](18-production-m1-delivery.md)。

## 3. 建议采用的设计默认值

| 编号 | 建议 | 原因／何时复议 |
| --- | --- | --- |
| D01 | 模块化业务 Host + MAF Worker | 保持业务简单，隔离 SDK 与 AOT 风险 |
| D02 | Web HTTP/SSE，内部 stdio 协议 | 兼顾浏览器、Docker 与未来桌面；实时桌面控制时评估 WS |
| D03 | 单所有者、单 Host、单工作区写入 | 符合 OPC；多机协作时重评调度与数据库 |
| D04 | app.db 主数据 + index.db 派生索引 | 查询重建不会误删业务记录 |
| D05 | 显式资源引用优先于物理 symlink | 减少 Windows／Docker／备份差异 |
| D06 | 按模板临时组队，控制递归和并发 | 避免无限增员与成本失控 |
| D07 | 单 Agent 优先，确有独立工作或复核时分工 | 减少协调和上下文重复成本 |
| D08 | 插件兼容分级，首版聚焦技能与 MCP | 格式可导入不等于平台运行时与云授权可复用 |
| D09 | 本地资料处理可设置禁止云发送 | 本地存储和本地推理是不同保证 |
| D10 | 默认记录业务事件，不展示隐式推理过程 | 用户需要可核对的操作与成果依据 |
| D11 | 任务优先，项目可选；纯问答可独立，执行自动建轻量 Task | 不要求先配置组织；执行与验收有业务归属 |
| D12 | Role/Agent/Task/Run/Attempt/Operation 分开 | 稳定责任、临时身份、恢复尝试和真实效果不能混为一物 |
| D13 | 一个责任人、默认一个主执行租约；改派先停旧写者 | DB fencing 不代表旧进程已停止；并行用子任务表达 |
| D14 | 子任务关系、等待条件、预算和取消意图持久化 | 重启后仍能等待、去重、接管；不靠内存 Promise |
| D15 | Task Done 绑定当前 revision 和固定成果版本的验收 | 区分计划决定、动作审批与成果验收；Run 成功仅产生候选成果 |
| D16 | 记忆候选/发布/版本/作用域独立，私有共享需发布 | 压缩和 RAG 不自动成为事实；冷热不等于删除 |
| D17 | 恢复四层分别验收；写前保存 Operation，未知效果先核对 | 会话能打开不代表副作用可重放；审批与恢复屏障不能由插件绕开 |
| D18 | 旧备份恢复先检查，无法获得较新遗忘记录时停用自动记忆注入 | 旧快照不能知道其后的发送或删除，不宣称自动防复活 |

这些是方案建议，后续可根据真实使用修订，不冒充用户逐项批准。

## 4. 未确定但不阻塞本轮设计

- 最终产品名、开源／商业模式、首批真实用户和付费方式。
- 第一个最常用的岗位模板及示例行业；目前使用通用模板。
- 第一批实测模型、实际账号和可接受的每任务／每日费用。
- 知识库真实规模、文件种类、OCR 使用频率和仅本地处理比例。
- 是否需要 macOS x64、Windows arm64、Linux arm64 首发；基线先验证 win-x64/osx-arm64/linux-x64。
- 自动长期建岗、共享记忆发布和高风险动作的具体授权范围；当前默认临时委派受预算限制，长期建岗与共享发布另行确认，见 04/06。
- Electron 已确认后加；若未来调整优先级，再变更 U09。
- SMTP 服务商、发件身份、真实收件人与汇报频率。

实施前需要确认对应资源和验收样本，不需要为了写设计把这些问题全部一次问完。

## 5. 必须由实验回答

MAF 在选定版本的审批／会话恢复行为、AOT Host 的实际依赖链、供应商工具调用兼容性、JSON Schema 验证器 AOT、SQLite 原生包跨 RID、中文检索质量、向量规模延迟、真实 SMTP 超时窗口、容器工具隔离能力。

没有运行证据时状态都是未验证；不能用框架 README、截图或成功调用一次聊天来替代这些门槛。

## 6. 当前不采用

纯文本文件与 SQLite 双向主存、每个岗位一个常驻服务、所有任务都群聊协商、无限递归建 Agent、把 prompt 当权限控制、审批完允许参数漂移、外部动作超时就自动重试、把工具全部动态加载进 AOT Host、复制企业级组织权限系统、把产品绑定到 Electron 主进程。
